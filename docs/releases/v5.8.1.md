## AI-Net-Guard v5.8.1 发布说明 (Release Notes)

补丁版本：把 v5.8.0 优化后的**真实提权实测数字**补进来，并修掉两处会误导的表述。防护逻辑本身与 v5.8.0 一致，无行为回退。

### 一、提权实测：单次自愈 20.7 s → 5.1 s

在真实 SYSTEM 上下文（提权终端跑 `17-autorepair-task.ps1 -Install -SelfTest`）：

| 版本 | run 1 | run 2 | 退出码 |
| --- | --- | --- | --- |
| v5.7.7 | 20.69 s | 21.18 s | 0 / 0 |
| v5.8.0 / v5.8.1（同一自愈路径） | **5.09 s** | **5.17 s** | 0 / 0 |

剩余 5 s 的构成：任务计划程序启动 + SYSTEM 冷进程约 2 s、`-OnNetworkEvent` 的 350 ms 预延时与 800 ms 后置复核、脚本自身约 2.1 s（其中 1.33 s 是 PowerShell 启动 + 148 KB 脚本解析）。再往下压只能靠缩减脚本体积或换宿主，已到合理地板。

### 二、`17 -SelfTest` 补齐兜底腿

`-Install -SelfTest` 原本只验证事件任务（跑两次），**60 分钟兜底任务在全新安装上永远是 `last run: never / result: 267011`**——也就是说这套安全网从来没被证明过能用。

现在追加一次兜底任务实跑（`07-mode.ps1 -Mode Auto -Quiet`，与定时器触发完全同一条路径），输出形如：

```
    run 1   : 5.09 s   result: 0 (success)
    run 2   : 5.17 s   result: 0 (success)
    fallback: X.XX s   result: 0 (success)
```

（`fallback` 那一行的耗时首次跑出来才知道，不预先编数字——本版修的正是"静态耗时写死"这个毛病。）三条退出码全为 0 才判定通过（否则 exit 4，并提示分别用 `Get-ScheduledTaskInfo` 查哪一条失败）。

### 三、去掉会腐烂的静态耗时数字

`-Status` 的 `cost` 行原本硬编码「fallback ~17 s, event repair ~21 s per fire」，v5.8.0 优化后这句已经失真，而写进输出的数字没人会记得同步更新。改为只描述触发模型：

```
cost   : 0 MB idle RAM, 0 % idle CPU ; fires only on boot / network change / wake + a 60-min timer
         (no wall-clock guess here on purpose - measure it with -Install -SelfTest)
```

耗时一律以 `-Install -SelfTest` 的实测为准。`17-autorepair-task.ps1` 的头注释同步改为实测值。

- GitHub Actions：`CI Build & Smoke Test` 与 `Build & Release GUI Executable` 均通过（run id 见下方 Checks）。

### 升级提示

若已按 v5.8.0 同步过生产目录，本版只需重新同步 + 重跑自检（提权终端）：

```powershell
.\13-harden-acl.ps1 -Root "C:\AI-Net-Guard" -SyncWorkspace -WorkspaceRoot <repo> -SkipVerification
.\17-autorepair-task.ps1 -Root "C:\AI-Net-Guard" -Install -SelfTest
```

第二条现在会多打一行 `fallback:`，那就是 60 分钟兜底任务的真实耗时。
