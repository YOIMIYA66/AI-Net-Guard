## AI-Net-Guard v5.8.8 发布说明 (Release Notes)

基于 v5.8.7 实机部署状态与全代码二次审查的加固收口版本：修复了实机发现的两项 P0 自愈缺陷（重启/换网后 `ActiveStore` `/32` 路由未恢复、嵌套数组导致三处自愈静默失效）、两项 P1 策略冲突与 `sing-box` 解析误报、四项 P2 体验与体检细节；同时从 [claude-desktop-killswitch](https://github.com/yoruuuchan/claude-desktop-killswitch) 吸收了 WFP `5157` 阻断归因、严格 RFC 5389 STUN 应答解析与 `ActiveStore` 规则段数回读核验三项验证能力。

---

### 一、P0：自愈链路关键修复

1. **重启/切网后 `ActiveStore` `/32` 节点路由自动恢复（`07-mode.ps1`）**
   - 抽离 `Sync-NodeActiveHostRoutes` 与 `Remove-RedundantActiveCoreRules`：通过 `.NET` 物理网关 + `route.exe PRINT -4` 执行零 CIM 快检；一旦发现重启清空了 `ActiveStore`、Wi-Fi/热点切换导致网关变更、或存在 `PersistentStore` 副本，立即按最低复合跃点默认路由重写 `ActiveStore` `/32` 并更新 `backup\node-routes.meta`。
   - 无论 `Sync-NodeRuleFast` 命中 `config.json` 时间戳 fast-path 还是 `$alreadyExact` 分支均会执行上述校验，彻底解决 v5.8.7 改用 `ActiveStore` 后重启/切网不自愈的回归问题。
2. **消除 `07-mode.ps1` `return ,` 嵌套数组陷阱（修复实机现行缺陷）**
   - `Get-ActiveTunNamesFast` 与 `Get-ActivePhysicalNicsFast` 移除前导逗号返回，所有调用点统一用 `@(...)` / `[string[]]` 解包。
   - 修复实机发现的 `AI-Guard-Block-PhysicalIP-On-TUN` 因嵌套 `[string[]]` 触发 `Set-NetFirewallRule -InterfaceAlias` 异常而停留在旧 `/32` 未升级到 `/24` 的问题，同时恢复 `AI-Guard-Block-WebRTC-LocalIP-*` 漂移自愈与热插拔物理网卡 `Foreign-Physical` 同步。

---

### 二、P1 / P2：策略一致性、`sing-box` 解析与清理提速

- **`DisablePhysicalIpv6 = false` 与 IPv6 显式阻断解耦**：`lib-foreign-block.ps1`（新增 `-BlockPhysicalIpv6`）、`02-killswitch.ps1`（`-SkipIpv6Block`）、`07-mode.ps1` 与 `14-apply-policy.ps1` 协同联动——关闭「禁用物理网卡 IPv6」时同步禁用 `AI-Guard-Block-Foreign-Physical-IPv6` 并在 `-Status` 标为 `(disabled by policy)`，不再误封全部公网 IPv6。
- **`sing-box` 1.11+ 规则精准判定（`lib-stun-guard.ps1`）**：支持 `action="hijack-dns"`、`type="logical"`（`and`/`or` 递归合并）与 `invert` 语义，避免 DNS 劫持规则被误报为 `SHADOWED`；新增 `RuleCount` 字段（单条合并规则为 `1`，双规则对为 `2`），统一 `07` / `12` / `18` / `verify-leak-test` 的序号文案。
- **P2 细节收口**：
  - `07-mode.ps1` `Get-B1GuardState` 先规范化 `|` 与连续空白再返回及写缓存（10 段缓存行），消除 `watchdog.log` 的 `caveat` 重复日志；
  - `10-sync-node-rule.ps1 -PruneStaleNodeRoutes` 改为内存预过滤 + 管道批量 `Remove-NetRoute`，避免数百次串行 CIM 往返；
  - `09-rollback.ps1` 补清 `foreign-block.meta`；`14-apply-policy.ps1` 重建 `Allow-LAN` 补全 RFC1918 网段；
  - `12-regression.ps1` 新增物理网卡外网阻断（IPv4+IPv6）、`PhysicalIP-On-TUN` 与 `0 PersistentStore /32` 检查，并统一 4 处小写 `skipped` 为 `'SKIP - ...'`。

---

### 三、吸收自 `claude-desktop-killswitch` 的三项验证强化

1. **严格 RFC 5389 STUN 请求构造与响应解析（`lib-stun-guard.ps1` / `verify-leak-test.ps1` / `12-regression.ps1`）**
   - 新增 `New-StunBindingRequest`（加密随机 96 位 `TransactionId`）与 `ConvertFrom-StunResponse`（严格校验 `0x0101`、Magic Cookie、TransactionId 匹配、TLV 边界对齐，并同时支持 IPv4 / IPv6 `XOR-MAPPED-ADDRESS` 与 `MAPPED-ADDRESS` 解码），异常/伪应答直接标为 `malformed` / 失败，不再只判长度。
2. **WFP Security Event ID `5157` 阻断归因（`12-regression.ps1`）**
   - 新增 `Find-WfpBlockOrigin` 在物理网卡 TCP/UDP 直连被拒/超时后最佳努力回查 `Security` 日志 Event ID `5157`，在 `[PASS]` 摘要中附带内核 `FilterOrigin` 证据（未启用 WFP 审计时优雅降级，不误报失败）。
3. **`ActiveStore` 活跃策略与地址段数回读核验（`12-regression.ps1`）**
   - 除静态注册表外，新增 `-PolicyStore ActiveStore` 实时回读，确认 `AI-Guard-Block-Foreign-Physical`（段数 `>=100`）、`AI-Guard-Block-Foreign-Physical-IPv6`（含 `2000::/3`）、`AI-Guard-Allow-CN`（段数 `>=1000`）与 `AI-Guard-Allow-TUN` 真正在内核活跃表生效且未被截断。

### 五、本机同步与验收命令（管理员 PowerShell 执行）

在 **管理员 PowerShell** 中执行以下命令将 v5.8.8 同步到 `C:\AI-Net-Guard` 并完成本机 `AI-Guard-Block-PhysicalIP-On-TUN` 的 `/24` 自愈升级与全链路回归：

```powershell
# 1. 同步 v5.8.8 脚本至 C:\AI-Net-Guard 并收敛 ACL 历史备份（自动裁为最旧 1 份 + 最新 5 份）
powershell -ExecutionPolicy Bypass -File "C:\AI-Net-Guard\scripts\13-harden-acl.ps1" -Root "C:\AI-Net-Guard" -SyncWorkspace -WorkspaceRoot "C:\Users\86198\Documents\deepseek-harness\default-workspace\AI-Net-Guard" -SkipVerification

# 2. 运行自愈（将 AI-Guard-Block-PhysicalIP-On-TUN 从 /32 升级为物理网卡子网 /24）
powershell -ExecutionPolicy Bypass -File "C:\AI-Net-Guard\scripts\07-mode.ps1" -Root "C:\AI-Net-Guard"

# 3. 跑一轮包含 ActiveStore 回读、WFP 5157 归因与严格 STUN 探测的完整体检
powershell -ExecutionPolicy Bypass -File "C:\AI-Net-Guard\scripts\12-regression.ps1" -Root "C:\AI-Net-Guard"
```
