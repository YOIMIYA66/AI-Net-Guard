## AI-Net-Guard v5.8.3 发布说明 (Release Notes)

观测与可维护性小版本：把 v5.8.2 已验证的 B1 路由守卫**纳入自愈链的检测范围**，并把散落 7 处的 12 端口清单收敛为单一定义，接入构建回归门禁。**防护范围与 v5.8.2 完全一致，未放宽任何阻断，也未新增阻断；没有改动 WFP 规则、路由写入逻辑、三态遮蔽判定或 `PASSED WITH CAVEAT` 验收口径。**

v5.8.2 的三条披露（caveat / 12 端口范围 / 归因边界）在本版继续有效，见文末第六节。

---

### 一、P0：自愈链一直在修那个赢不了的层

一次真实审计发现的结构性缺口：

- `02-killswitch.ps1` 与 `07-mode.ps1` 每个周期都会自动重跑 `15-webrtc-browser-shield.ps1`；
- 但 `15` 自己的头部注释就写明：TUN 起来之后，浏览器把包交给隧道，核心从物理网卡重新发出，WFP 的 block filter 根本不会被求值；
- 真正在核心路由表里丢弃这批流量的 `18-route-stun-guard.ps1`，**全仓库零引用**——它是一次性写入，之后再没有任何机制检查它是否还在。

于是只要用户在 v2rayN UI 里切了路由集、升级了 v2rayN、或者手改了路由表，两条 guard 规则消失后**所有症状都是静默的**：物理网卡的 WFP 规则仍挡着同一批出口，探针照样 5/5 静默，而核心自己重发的包（防火墙看不到的那一个）直接出去。自愈链修的是挡不住的层，漏掉的是唯一挡得住的层。

**本版做法**：`07-mode.ps1` 新增 `Get-B1GuardState`，复用 `lib-stun-guard.ps1` 对 `binConfigs\config.json` 做只读形状判定。

| 位置 | 行为 |
| --- | --- |
| `-Status` | 新增 `B1 route guard` 行，显示 `loaded (12 ports, udp+tcp, routing rules #N and #N+1)`；`Shadow` / `Caveat` 转黄标，`absent` / `error` 红标并打印修复命令 |
| 每周期快检（9b 段） | 非 `present` 或 `SHADOWED` 写 `logs\watchdog.log` 的 `WARNING`，判定同时进 `backup\mode-state.json` 的 `B1Guard` 字段 |

**刻意不自动修复，也刻意不抬高退出码**：`18 -Apply` 要改写 `guiNDB.db` 且拒绝在 v2rayN 运行时执行，从 SYSTEM 计划任务里触发轻则被 v2rayN 退出时整体回写覆盖、重则损坏数据库；而用户主动换一套不带守卫的路由规则是合法选择，一个每小时都失败的任务只会让人学会忽略失败。检测 + 显著告警 + 精确的修复命令，是这个检查的全部职责。

### 二、P1：12 端口清单从 7 份硬编码收敛为 1 份定义

`02` / `07`（两处）/ `14` / `15`（两处）/ `18` / `verify-leak-test` 原先各抄一份 `3478,3479,5349,5350,19302-19309`。任意两份不同步，就会出现「WFP 挡 13 个端口、核心丢 12 个，两边都报健康」，而验收脚本会把这个代码问题误判成配置问题。

现在唯一定义在 `lib-stun-guard.ps1`，按用途提供三种形态：`Get-StunGuardPorts`（`int[]`，分析用）、`Get-StunGuardPortStrings`（`string[]`，`New-NetFirewallRule -RemotePort` 用）、`Get-StunGuardPortSpec`（逗号串，写路由规则用）。**缺库一律 `exit 1`，不回落本地字面量**——空端口列表会造出一条「挡住所有端口、却显示 `Enabled=True`」的规则，正是这类检查要防的静默失败。

### 三、P1：回归门禁进构建，测试脚本不进发行物

新增 `tests\test-stun-ports.ps1`，由 `gui\build.ps1` 在纯 ASCII + AST 语法门禁之后强制运行，失败即中断构建。断言覆盖：单一定义内容、三种 getter 一致、其余脚本无本地副本、6 个消费方**先加载 lib 再调用**（按行号比较，而不是只查字符串存在）、`09-rollback.ps1` 必须清理新增的 `b1-guard.meta`。`tests\` 只参与门禁，打包段独立从 `scripts\` 取文件，实测 payload 内不含 `tests\`。

### 四、完整 diff review 后修掉的 6 处

逐项自查 10 个文件（+374/−35）后修正：

1. `18` 的 `Get-ExpectedPortSet` 去掉一元逗号：`@(f).Count` 由 1（嵌套数组）改回 12，消除后来者踩坑的隐患；
2. B1 缓存 key 补上 lib 的 `(mtime, length)`：只按 config.json 缓存时，升级 lib 而配置不变会继续返回旧的 `present`，恰是这个 watch 要防的静默陈旧；
3. 9b 的空 `catch` 改为写 `WARNING`，不再吞掉检测自身的失败；
4. 删除只写不读的死变量 `$script:B1Warning`；
5. 两个 `Protected` 分支的 `Write-State` 补传 `-B1`，fail-closed 状态文件不再丢 B1 信息；
6. lib 路径查找对 `$PSScriptRoot` 为空做防御。

缓存行改为九段 `cfgTicks|cfgLen|libTicks|libLen|state|index|shadow|caveat|detail`，旧格式前缀不匹配即自动重算，无需手工清缓存。真机验证：临时 Root 冷启动写出 9 段，把 `state` 篡改成 `absent` 后再跑 `-Status`，输出 `absent - CACHE-HIT-PROBE`，证明读路径生效。

另外修正了一个作用域顺序问题：`-Status` 分支早于静态状态段执行，`Get-B1GuardState` 必须定义在 `Show-Status` 之前，实跑 `-Status` 已验证输出正常。

### 六、必须披露的边界（沿用 v5.8.2，并补充两条）

1. **`B1 ACTIVE with 1 caveat` 仍在**：guard 之前的 `out=direct, process=xray/sing-box/self` 规则没有端口与域限定，只被 process 收窄；**核心自身**发起的 STUN 不在守卫范围内。不写成「前置规则已全部排除干扰」。
2. **范围未扩大**：只覆盖 12 个端口（3478 / 3479 / 5349 / 5350 / 19302-19309）的 udp + tcp，对所有目标生效。`udp/443` 等非标 STUN/TURN 端口不在范围内，WebRTC 通话可能退化为中继或失败——这是 B1 的既定取舍。本版**没有**动这块，因为加 443 会连带打击国内 QUIC / HTTP/3。
3. **归因边界**：探针静默**不能**单独推出「包在核心内被丢弃」。同时生效的还有 WFP 层 `AI-Guard-Block-WebRTC-UDP`（program=Any，同 12 端口，Outbound Block），它同样能造成静默。v5.8.2 的隔离测试（关掉 5 条 WFP UDP 规则后 5/5 仍静默）才是核心侧丢弃的证据，本版没有重做该实验，结论沿用。
4. **本版新增的是检测，不是修复，也不是抓包**：9b 只回答「核心当前加载的路由表里还有没有这对规则」。修复仍需人工关闭 v2rayN 后运行 `scripts\18-route-stun-guard.ps1 -Apply`。
5. **升级后需同步生产目录才会生效**：`-SyncWorkspace` 只同步 `scripts\*.ps1`（不覆盖 `cn-ipv4.txt` / `ai-domains.txt` 等运行时数据）。同步完成前，实机跑的仍是 v5.8.2 脚本，`-Status` 不会出现 `B1 route guard` 行，也不会生成 `backup\b1-guard.meta`。这是发版与部署的时间差，不是故障。

### 升级方式

1. 用本版 `AI-Net-Guard.exe` 覆盖安装，或直接在管理员终端从仓库同步脚本：
   ```powershell
   powershell -ExecutionPolicy Bypass -File "C:\AI-Net-Guard\scripts\13-harden-acl.ps1" -Root C:\AI-Net-Guard -SyncWorkspace -WorkspaceRoot <仓库路径> -SkipVerification
   ```
2. 只读确认：`powershell -ExecutionPolicy Bypass -File "C:\AI-Net-Guard\scripts\07-mode.ps1" -Status`，应看到 `B1 route guard : loaded (12 ports, udp+tcp, ...)`。
3. 不需要重建 WFP 规则、不需要重跑 `18 -Apply`、不需要改 v2rayN 路由集。
