## AI-Net-Guard v5.8.0 发布说明 (Release Notes)

### 一、WebRTC 防泄漏：防线从防火墙搬到核心路由表

v5.7.x 把「8 条 Block 规则全部 `Active=TRUE`」当成 WebRTC 已封堵的证据，这次用**不经浏览器**的裸 UDP STUN 客户端复核，结论被推翻：

| 目标 | 结果 | 判定 |
| --- | --- | --- |
| `stun.miwifi.com:3478` | `mapped=183.188.38.12` | **真实宽带 IP 泄露** |
| `stun.chat.bilibili.com:3478` | `mapped=183.188.38.12` | **泄露** |
| `stun.l.google.com:19302` | `mapped=20.89.232.246` | 走代理，正常 |

当时规则的程序路径、12 个 STUN 端口、网卡 GUID 全部正确。真实链路是 `任意进程 → xray_tun → xray 命中 geoip:cn → direct → 从物理网卡重发`，卡在最后一跳。

根因不是「规则不够具体」——Windows 防火墙的仲裁是**显式 Block 一律压过 Allow**。真正原因是 TUN 提供方在 `ALE_AUTH_CONNECT` 层对核心自身的出站安装了 callout，直接 **PERMIT 并终结分类**，Block 过滤器根本没有被求值。旁证：同一个探针若显式绑定物理地址，规则一定生效。**这一跳任何防火墙规则都堵不住。**

- **新增 `scripts/18-route-stun-guard.ps1`（方案 B）**：唯一能在重发前看到包的层次是核心自己的路由表。照抄 v2rayN 自身「阻断 udp443」的手法，在当前生效路由集**顶部**插入 `3478,3479,5349,5350,19302-19309 → block`（UDP + TCP）。包在核心内被丢弃，不产生任何出站。
  - **国内直连规则一行不动**，`geoip:cn` / `geosite:cn` 位置与语义不变，**代理流量零增加、配额不受影响**。
  - `-Verify`（默认）只读体检；`-Apply` 先把 `guiNDB.db` 备份到 `backup\v2rayn-routing\<时间戳>\` 再写；`-Restore` 一键回滚；**v2rayN 运行中拒绝执行**（其内存副本会在退出时覆盖数据库）；以 `STUN-GUARD:` 前缀做幂等剥离，重复执行不叠加；写入后回读校验，读不到即 exit 3。
  - **代价（显式取舍）**：网页版 WebRTC 通话拿不到 `srflx` 候选，可能只能走 TURN 中转或直接建连失败。这是「宁可不通也不泄露」，随时可 `-Restore` 撤销。
- **`verify-leak-test.ps1` 新增第 9 段活体探针**：旧的验收方式只数规则，恰好是「规则全绿但仍在泄露」时也会通过的那个检查。现在直接对 3 个境内 + 1 个境外 STUN 服务器发真实 Binding Request，判定标准是**行为**——TUN 在线时境内 STUN 不得有任何应答；超时判定改按 `SocketErrorCode`，不再依赖会被本地化的异常文本。

### 二、自愈快路径重构：单次自检 5.8 s → 2.1 s

| 缺陷 | 后果 | 修法 |
| --- | --- | --- |
| `Test-ShieldDriftFast` 用 `IF=\{GUID\}` 匹配，而 `NetworkInterface.Id` 自带花括号，拼成双层 `IF=\{\{...}}` 永不匹配 | 每轮自检都误判「漂移」，每次都拉起 `15-webrtc-browser-shield.ps1` 子进程，白烧约 3.5 s | 统一为带花括号形式后逐字比较；注入幻影网卡 GUID 反向验证门控两个方向都正常 |
| `backup\foreign-block.meta` 用 `-Encoding ASCII` 写签名，而签名含网卡别名（`以太网`） | 别名被写成 `???`，签名永远不等 → 只要以太网 Up 就删掉再重建整条上千条 `RemoteAddress` 的 `AI-Guard-Block-Foreign-Physical`，且**删除到重建之间有无显式 BLOCK 的 fail-open 窗口** | meta 改 UTF-8 读写；已有规则改用 `Set-NetFirewallRule -RemoteAddress` 原地更新，空窗消失 |

实测（非提权、同机、各 3 次取最小值）：`5789 / 6310 / 6012 ms` → `2113 / 2210 / 2168 ms`。剩余 2.1 s 中约 1.33 s 是 PowerShell 进程启动 + 148 KB 脚本解析，已到地板。

同时为 `07-mode.ps1` 与 `15-webrtc-browser-shield.ps1` 各加了 `RuleIndex` + `RuleFilterCache` 两层规则集缓存（`Get-NetFirewallRule` 单次约 1233 ms，每个 `Get-NetFirewall*Filter` 约 290~337 ms），并强制「任何写操作后必须 `Reset-RuleCache`」。对健康路径收益接近零，但对 `15` 自身显著：`-Verify` 45.1 s → 11.9 s，`-Apply` 12.4 s → 6.6 s，`-DryRun` 32.4 s → 7.8 s。

### 三、升级提示

1. 直接运行新版 `AI-Net-Guard.exe` 应用防护即可，`07-mode.ps1` 的改动会自动生效。
2. 若要让 WebRTC 泄露真正关闭：**完全退出 v2rayN** → `scripts\18-route-stun-guard.ps1 -Apply` → 重新启动 v2rayN → `scripts\verify-leak-test.ps1` 看第 9 段。
3. 切换 effective 路由集（Blacklist / Global）或升级 v2rayN 重写数据库后，需要重新 `-Apply`；平时用 `-Verify` 检查。
