## AI-Net-Guard v5.8.7 发布说明 (Release Notes)

针对 **v5.8.6** 现网实机状态与全仓库代码的深度审查收口版本：根治了本机已触发的持久化 `/32` 主机路由污染问题（P0），并补齐了 `sing-box` 内核 B1 观测、物理网卡 IPv6 显式阻断、`14-apply-policy.ps1` 三处增量更新缺陷及多项规则卫生与观测口径修复（P1/P2）。

> 本版继续保持「有限结论」与「不扩权」原则：B1 核心路由守卫仍仅做只读检测、不自动改写 `guiNDB.db`；STUN/TURN 覆盖范围与 `PASSED WITH CAVEAT` 三段披露口径与 v5.8.6 一致。

---

### 一、P0：根治持久化 `/32` 路由污染与历史孤儿路由清理

实机审查发现在主机 `PersistentStore` 持久化路由表中积压了 **368 条 `/32` 主机路由**（除当前节点外多达 367 条历史孤儿路由，覆盖大量 Cloudflare / AWS / Fastly CDN 及国内 IP）。

- **根因**：`02-killswitch.ps1`、`07-mode.ps1`、`10-sync-node-rule.ps1` 此前会扫描 v2rayN 批量测速生成的临时文件 `binConfigs\configTest*.json`，将订阅测速节点 IP 合并后调用未加 `-PolicyStore` 的 `New-NetRoute`（Windows 默认写入永久 `PersistentStore`），而清理逻辑仅保留前一次 `node-sync.meta` 的差集。
- **修复**：
  1. `02` / `07` / `10` 全部移除 `configTest*.json` 扫描，仅授权活跃 `binConfigs\config.json` 出站节点；
  2. `07` / `10` 创建 `/32` 路由强制指定 **`-PolicyStore ActiveStore`**（绝不持久化），并自动清理同名 `PersistentStore` 副本；新增独立路由账本 `backup\node-routes.meta`，卸载脚本 `09-rollback.ps1` 同步清理两类 store 与该账本；
  3. `10-sync-node-rule.ps1` 新增 **`-PruneStaleNodeRoutes`** 参数，可一键安全清扫历史遗留的非私网物理网卡 `PersistentStore` `/32` 孤儿路由。

---

### 二、P1：多内核 B1 观测、物理网卡 IPv6 否决与策略引擎修复

1. **`lib-stun-guard.ps1` 适配 `sing-box` schema**：
   - `Get-TunInboundTags` 同时识别 `protocol="tun"`（Xray）与 `type="tun"`（sing-box）；
   - 新增 `sing-box` `route.rules` 解析（支持 `action="reject"` / `outbound="block"`、`port` / `port_range` 规则、双条或单条合并规则，以及 `inbound` / `ip_cidr` / `rule_set` / `process_name` 等字段三态遮蔽判定）；
   - 新增无文件 I/O 的 `Get-StunGuardAnalysisFromObject` 供构建门禁零副作用全覆盖测试。
2. **`lib-foreign-block.ps1` 补齐物理网卡 IPv6 显式 `Block`**：
   - 新增 `AI-Guard-Block-Foreign-Physical-IPv6`（在所有物理网卡上显式 `Action=Block` 拦截 `2000::/3` 全局单播 IPv6），与 IPv4 规则协同否决火绒等第三方 WFP 驱动的软放行（消除热插拔新网卡 5 秒事件窗口或放开 IPv6 开关时的潜在窗口期）；
   - `07-mode.ps1` 的规则白名单校验、`-Status` 展示与 `Ensure-Guard` 第 10 段同步接管该规则。
3. **`14-apply-policy.ps1`（及 `02`/`07` 协同）修复三处回退与错位**：
   - `AI-Guard-Block-PhysicalIP-On-TUN`（`02`/`07`/`14`）及 `14` 中的 `AI-Guard-Block-WebRTC-LocalIP-UDP/TCP` 统一使用物理网卡子网 CIDR（与 TUN 网段重叠时回落 `/32`），避免增量应用覆盖回裸 `/32`；
   - 关闭 `BlockWebRtcLeak` 时，`14` 调用 `15-webrtc-browser-shield.ps1 -Remove -Quiet`，且 `14` 与 `07` 同步禁用 `*-PhysUDP` 与 `*-CoreSTUN-*` 浏览器/核心规则；
   - 删除 `14-apply-policy.ps1` 中误置在 `DisableLlmnrNetbios = OFF` 分支内的 `DiagTrack` / `dmwappushservice` 遥测禁用代码。

### 三、P2：规则卫生、观测口径对齐与日常运维优化

- **僵尸核心规则与失效 TUN GUID 清理**：`07-mode.ps1` 与 `10-sync-node-rule.ps1` 对当前主核心自动清理重复的 `AI-Guard-Allow-Core-<ActiveCore>-*`（清掉切核前遗留的旧端口规则），并在非 UDP 节点时扫除全部 `AI-Guard-Allow-Core-*-UDP`；`07-mode.ps1` 在 TUN 在线时剪除 `Allow-TUN` / `Allow-TUN-Alt` / `Block-PhysicalIP-On-TUN` 上已不存在的旧适配器 GUID。
- **非提权 `-Status` 计划任务口径**：`07-mode.ps1 -Status` 在非管理员会话下无法枚举 `SYSTEM` 计划任务时，改为输出黄字 `inconclusive` 与最近 `mode-state.json` 更新时间（与 `17-autorepair-task.ps1` 对齐），不再误报 `none registered`。
- **路径与防堆积优化**：
  - `02` / `10` / `14` / `18` 统一纳入 `v2rayN-windows-64-desktop` 探测路径，`18-route-stun-guard.ps1` 移除硬编码默认路径；
  - `07-mode.ps1` 9b 段仅在 B1 `State`/`Caveat`/`Detail` 变化时写入 `watchdog.log`，减少每小时重复刷屏；
  - `13-harden-acl.ps1` 限制 `backup\acl-before-*.txt` 最多保留「最旧 1 份基线 + 最新 5 份」；
  - `09-rollback.ps1` 解决老遗留项：`Log` 写入改用 UTF-8 无 BOM（`AppendAllText` + `UTF8Encoding($false)`），保留本地化日志字符。

### 五、本机升级与一键清理命令（管理员 PowerShell 执行）

在 **管理员 PowerShell** 中依次执行以下 4 步即可完成本机部署、清扫 367 条历史 `/32` 路由、拉起 IPv6 显式阻断并验收全链路：

```powershell
# 1. 同步 v5.8.7 脚本到 C:\AI-Net-Guard 并重新锁定 ACL
powershell -ExecutionPolicy Bypass -File "C:\AI-Net-Guard\scripts\13-harden-acl.ps1" -Root "C:\AI-Net-Guard" -SyncWorkspace -WorkspaceRoot "C:\path\to\AI-Net-Guard" -SkipVerification

# 2. 清理本机历史遗留的 367 条 PersistentStore /32 孤儿路由并裁剪冗余 Core 规则
powershell -ExecutionPolicy Bypass -File "C:\AI-Net-Guard\scripts\10-sync-node-rule.ps1" -Root "C:\AI-Net-Guard" -PruneStaleNodeRoutes

# 3. 执行一轮自愈检查（创建 AI-Guard-Block-Foreign-Physical-IPv6 并剪除僵尸 TUN GUID）
powershell -ExecutionPolicy Bypass -File "C:\AI-Net-Guard\scripts\07-mode.ps1" -Root "C:\AI-Net-Guard"

# 4. 跑完整回归体检确认 PASS / FAIL=0
powershell -ExecutionPolicy Bypass -File "C:\AI-Net-Guard\scripts\12-regression.ps1" -Root "C:\AI-Net-Guard"
```
