## AI-Net-Guard v5.9.4 发布说明 (Release Notes)

**双引擎热修维护版 (Hotfix Patch Release)**：在 v5.9.3 基础上修复 PowerShell 7.x（.NET Core / .NET 5+）下 `Enter-GuardWriteLock` 无法调用 4 参数 `System.Threading.Mutex` 构造函数的问题，完整打通 Windows PowerShell 5.1 与 PowerShell 7.x 双引擎本地与提权执行路径。

---

### 一、相较 v5.9.3 的修复内容

1. **修复 PowerShell 7.x 下 `Enter-GuardWriteLock` 写锁创建兼容（[`lib-guard-common.ps1`](../../scripts/lib-guard-common.ps1)）**
   - **根因**：Windows PowerShell 5.1（.NET Framework）支持 `New-Object System.Threading.Mutex($false, $LockName, [ref]$createdNew, $mtxSec)` 四参数构造，而 PowerShell 7.x（.NET Core）已将该安全描述符构造迁至 `[System.Threading.MutexAcl]::Create`；因此在 PowerShell 7.x（如 `pwsh 7.7`）中直接运行 `07-mode.ps1`、`12-regression.ps1`、`14-apply-policy.ps1` 或 `09-rollback.ps1` 时，会在获取 `Global\AI-Net-Guard-PolicyEngine` 写锁阶段报错退出。
   - **修复**：运行时按是否存在 `System.Threading.MutexAcl, System.Threading.AccessControl` 自动分流至 `[System.Threading.MutexAcl]::Create(...)` 或传统 4 参数构造，并在异常捕获后补全 `if (-not $mtx)` 空句柄保护，保留 `Global\` 命名空间与 `Administrators`/`SYSTEM` ACL 约束不变。

2. **新增双引擎门禁断言（[`test-stun-ports.ps1`](../../tests/test-stun-ports.ps1)）**
   - 门禁断言扩至 **59 项**，覆盖 `MutexAcl` 分支与空句柄保护，并在 Windows PowerShell 5.1 与 PowerShell 7.7 双引擎下分别全量跑通（含跨引擎 `pwsh` 与 `powershell.exe` 真实双进程 `Global\` 写锁争用）。
