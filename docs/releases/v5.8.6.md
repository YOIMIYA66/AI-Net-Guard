## AI-Net-Guard v5.8.6

v5.8.5 发布后的终审收口版本。本版**不改变任何防护范围**：12 个 STUN/TURN 端口的 udp+tcp 阻断、WFP 规则、核心路由表 B1 写入逻辑、`PASSED WITH CAVEAT` 验收口径全部与 v5.8.5 一致；改动集中在「体检结论如何在 GUI 归因」与「前置规则的三态遮蔽判定是否自洽」。

### 一、GUI 不再把「有跳过项」当成「全项通过」

v5.8.5 修好了 `12-regression.ps1` 的 `Check()`：B1 在 v2rayN 未运行、核心路由表不存在时返回 `SKIP`，不再被计成 `PASS`，结果行追加 `SKIP=n`。但**当时发布说明里列为症状的第三项——「GUI 弹出全项体检通过」——并未真正修掉**：`RegressionBtn_Click` 只判 `code == 0`，而 `12` 的 exit code 在有跳过项时仍是 0。于是绿色 pill「全项体检通过 (PASS)」、弹窗「系统处于零泄漏健康状态」、副标题「零泄漏健康验证」原样保留，与项目自 v5.8.2 起「不得绝对化归因」的口径冲突。

本版在输出回调里同步捕获控制台流（`ConcurrentQueue<string>`，不阻塞 UI 线程），用 `SKIP=(\d+)` 读取结果行的跳过数，缺结果行时退回统计 `[SKIP]` 行数，形成三态：

| 条件 | 界面 | 色调 |
| :--- | :--- | :--- |
| `exit 0`，无跳过项 | 「体检完成 (FAIL=0)」；正文显式说明**不覆盖**非常规 STUN/TURN 端口（含 udp/443）与 origin-scoped 直连规则 | Success |
| `exit 0`，有 N 项跳过 | 「体检完成，N 项未执行」；明确「跳过不等于通过」，提示 v2rayN 未运行时先启动再重跑 | Warning |
| `exit != 0` | 「体检有未通过项」，指向控制台 | Danger |

同时移除全部「零泄漏健康状态 / 零泄漏健康验证」绝对化措辞，并把成功 / 跳过 / 失败三支弹窗的标题、正文、按钮、副标题改为中英双语（此前英文模式下弹窗仍是中文）。

**`12-regression.ps1` 的 exit code 语义与输出格式未动**，v5.8.5 发布说明所称「与既有 GUI 判定兼容」仍然成立；变化只在展示层。

### 二、`ip` 早返回与 `attrs` 漏判（与 v5.8.5 同一 bug 模式）

`lib-stun-guard.ps1` 的 `Get-StunRuleVerdict()` 里，`ip` 分支在收敛循环**之前**就 `return matches`；`StunNarrowingKeys` 早已收录 `attrs`，收敛循环却没检查它。终审行为探针实测：

| 前置规则形状 | v5.8.5 | v5.8.6 |
| :--- | :--- | :--- |
| `ip` 单独 | `matches`（完整遮蔽） | `matches`（**保持不变**，保守） |
| `ip + process` | `matches` → 假 `SHADOWED` | `restricted`（caveat） |
| `ip + protocol` | `matches` → 假 `SHADOWED` | `restricted`（caveat） |
| `attrs` 单独 | `matches` → 假 `SHADOWED` | `restricted`（caveat） |

修法：`ip` 分支只设置 `matches` 初判、**不再 return**，让后续收敛循环继续判定；循环补入 `attrs`。这与 v5.8.5 修的 `inboundTag` 早返回 / `protocol` 漏判是同一个模式，遵循「配置里无法证明排除就显式披露，而不是擅自判定排除」的既定口径。

真实核心配置复验**未漂移**：`present / index=5 / shadow=0 / caveat=1 / preceding=3`，与 v5.8.5 完全一致。当前生效规则集未触发这两种形状，属潜在缺口修复，不改变现网判定结果。

### 三、回归门禁

`tests\test-stun-ports.ps1` 从 **21 条扩到 24 条**，新增：

1. `ip` 单独仍是 `matches`，但 `ip + process` / `ip + protocol` 必须是 `restricted`；
2. `attrs` 形状必须与 `StunNarrowingKeys` 一致，判 `restricted`；
3. GUI 必须捕获 `SKIP=n` 与 `[SKIP]`、在跳过时使用 `Warning` 色调，且不得再出现绝对化「零泄漏健康」文案。

对第 3 条额外做了**负向变异测试**：把旧文案塞回 GUI 源文件的内存副本后，断言结果由 `True` 变 `False`，确认不是编码问题造成的「假通过」。同时把门禁里 `$gui` 的读取显式改为 `-Encoding UTF8`，避免 PowerShell 5.1 按 ANSI 读取 BOM-less 中文文件产生乱码、让中文检测形同虚设。

### 五、边界与如实披露

1. **本版没有实跑 `12-regression.ps1` 全量体检**：它含 10 秒 `pktmon` 抓包、临时 WFP 导出与 geo 文件写入，需提权且有系统副作用。`PASS=27 FAIL=0` 是 v5.8.4 改动前的实机结果；本版靠构建门禁、行为探针、负向变异测试与配置级探针验证新增逻辑，**不等于整份体检在 v5.8.6 真机跑过**。
2. **GUI 三态未做真机点击验证**：冒烟测试只覆盖 UI 实例化与载荷解包，点击「全量回归体检」需提权且会启动抓包。三态逻辑由编译通过、门禁文本约束与解析逻辑等价复现共同保证，未冒领实机点击结果。
3. **GUI 只读脚本输出，不改写脚本结论**：若未来输出格式变化，`SKIP=n` 解析会退回 `[SKIP]` 行计数；两者都缺失时回到「体检完成 (FAIL=0)」。门禁第 14 条约束这段代码不得回退。
4. **防护范围未变**：仍是 12 端口 udp+tcp，`udp/443` 与 origin-scoped direct 的 caveat 保持；`PASSED WITH CAVEAT` 三段披露逐字未动；`-Apply` / `-Restore` 一律人工，B1 不自动修复。
5. **未改的 follow-up**：`09-rollback.ps1` 的 `Log` 仍用 `Add-Content -Encoding ASCII`，本地化日志文本会变 `?`。

### 六、升级与验收

1. **GUI 升级**：下载 `AI-Net-Guard.exe` 直接运行，点击「应用策略」即可解包部署最新引擎。
2. **生产脚本同步**（需**提权 PowerShell**，本会话无管理员权限）：
   ```powershell
   powershell -ExecutionPolicy Bypass -File "C:\AI-Net-Guard\scripts\13-harden-acl.ps1" -Root "C:\AI-Net-Guard" -SyncWorkspace -WorkspaceRoot "C:\Users\86198\Documents\deepseek-harness\default-workspace\AI-Net-Guard" -SkipVerification
   ```
3. **真机全量体检**（同一提权窗口，含 10 秒抓包，约 25 秒）：
   ```powershell
   powershell -ExecutionPolicy Bypass -File "C:\AI-Net-Guard\scripts\12-regression.ps1" -Root "C:\AI-Net-Guard"
   ```
4. **验收口径**：v2rayN 运行时 `B1 STUN route guard` 应为 `[PASS]` 并附带 caveat 披露，结果行 `SKIP` 不出现、GUI 显示绿色「体检完成 (FAIL=0)」；若在维护窗口临时关闭 v2rayN，该项应为灰色 `[SKIP]`、结果行出现 `SKIP=1`，GUI 应显示**黄色**「体检完成，1 项未执行」，而**不再**是绿色「全项体检通过」。
